# 业务事实与准入核查

在业务事实尚未结构化、涉及多主体合作或需要核查许可时阅读。

## 事实表

建议字段：事实编号｜待核事项｜当前事实或假设｜来源与位置｜事实状态｜影响的判断｜需补材料。

优先提取以下信息，不向用户一次性索要所有文件：

| 维度 | 决定定性的事实 | 常用证明材料 |
| --- | --- | --- |
| 主体 | 注册地、股权及控制、境内外主体、实际运营者、分支机构 | 登记资料、股权图、合作协议 |
| 服务与客群 | 功能、交付对象、B2B/B2C、未成年人或其他特殊群体 | 产品说明、用户旅程、真实页面 |
| 收费与资金 | 谁定价、收款、归集、结算、退款，是否保本或提供信用 | 收费规则、支付链路、结算合同 |
| 商品与履约 | 谁生产、销售、进口、交付、售后，是否自营或混营 | 订单样本、履约和售后流程 |
| 数据 | 来源、字段、敏感性、用途、共享、保存、境外访问 | 数据地图、接口说明、处理协议 |
| 内容与算法 | 谁生产、审核、推荐内容，是否使用生成式能力 | 内容规范、审核机制、功能演示 |
| 地域与阶段 | 经营地、用户地、服务覆盖地、试点范围、上线时间 | 运营计划、落地安排、存量记录 |
| 合作与控制 | 谁掌握账户、系统、人员、合同及重大决策 | 职责分工、权限表、实际操作记录 |

对页面展示与合同约定不一致，或合同与实际履行不一致的，分别记录。不要为了使结构图完整而补造缺失环节。

## 最小问题集

根据具体缺口选择能改变结论的问题，例如：

- 平台是否接触客户资金，还是仅跳转至独立支付机构？
- 系统是否给出个体诊断、处方或投资建议，还是提供一般信息？
- 服务由哪个主体实际提供，拟使用的资质由哪个主体持有？
- 境外团队能否访问境内用户数据，访问哪些数据、用于什么目的？

如果暂不能回答，以条件分支继续：“若存在 X，则需核查 A；若仅为 Y，则优先核查 B”。清楚标注尚未确定分支。

## 准入核查表

活动编号｜实际活动｜监管定性及备选定性｜主管机关｜禁止/限制情形｜许可、备案等要求｜触发条件及例外｜申请或持证主体｜范围、地域和有效期｜现有证据｜缺口｜上线前置条件｜依据编号。

判断顺序：

1. 核对是否允许从事该类活动，以及主体、地区、客群、资金或技术方面的限制。
2. 确认资质究竟约束主体、场所、人员、产品、设施还是单项活动。
3. 核验取得时间与业务开展时间；已提交申请不等于已获许可。
4. 对续期、变更、异地经营、业务扩张及实际控制变更，核查是否触发额外手续。
5. 对豁免或试点，逐项核实适用条件和证明材料；缺少证明时不直接适用。
6. 区分强制准入与行业推荐资质、商业合作要求；商业必要不等于法定义务。

官方公示查询应保存查询时间、网址和结果范围。“未查到”可能源于名称、覆盖范围或系统延迟，不能直接写成“无证”。资质真实性、覆盖范围和实际使用方式是不同问题。

## 合作模式的实质检查

对于“平台＋持牌机构”“技术公司＋医疗机构”等安排，比较合同分工与实际操作：客户由谁获取、合同由谁订立、核心决定由谁作出、费用归谁、风险由谁承担、投诉由谁处理。主体独立持证及职责安排必须共同支持结论。

输出可采用简明主体—活动表。只有多条流转路径影响判断时才画结构图，资金流和数据流分别标明。
